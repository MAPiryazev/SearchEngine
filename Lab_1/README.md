
## ЛР1: Добыча корпуса документов
В этой лабораторной собирается корпус документов из двух источников — русская Википедия и ru.stackoverflow.com. Дальше этот корпус используется в следующих ЛР для построения индексов и реализации поиска.

## Источники данных

### Русская Википедия (Wikimedia Dumps)
Для Википедии используется официальный дамп Wikimedia `ruwiki-latest-pages-articles.xml.bz2` из каталога `ruwiki/latest/`. Это XML-дамп: у каждой страницы есть ревизии, а исходный текст хранится в `<revision><text>` и содержит wiki-разметку (ссылки, шаблоны `{{...}}`, HTML-теги и т.п.) [web:42]. При подготовке корпуса из этого текста вычищается разметка, нормализуются пробелы, а также сохраняются основные поля вроде `title`, `id` страницы и `timestamp` ревизии.

### Stack Overflow на русском (Stack Exchange Data Dump)
Для ru.stackoverflow.com берётся Stack Exchange Data Dump; основной файл с контентом — `Posts.xml` [web:47]. Внутри `Posts.xml` встречаются разные типы постов: `PostTypeId="1"` — вопрос, `PostTypeId="2"` — ответ [web:47]. Текст поста хранится в HTML (поле `Body`), поэтому перед сохранением в корпус HTML очищается, а кодовые блоки при необходимости заменяются маркером, чтобы они не доминировали в тексте.

## Что именно сохраняется

### Википедия
На входе: XML + wiki-разметка в `<revision><text>` [web:42].  
На выходе: очищенный текст без разметки и мета-информация (например заголовок и идентификатор страницы), достаточная для дальнейшей индексации.

### Stack Overflow
На входе: `Posts.xml` из Stack Exchange dump [web:47].  
На выходе: очищенный текст поста + мета-поля (Id, дата, теги, score и т.д.), чтобы потом можно было анализировать качество и/или фильтровать документы.

## Итоговый формат (JSONL)
Результат сохраняется в `docs.jsonl`: каждая строка — отдельный JSON-объект (один документ).

Минимальный набор полей:
- `id`: внутренний идентификатор (0..N-1)
- `external_id`: идентификатор в исходном источнике
- `source`: `"wiki"` или `"stackoverflow"`
- `title`: заголовок
- `text`: очищенный текст
- `meta`: дополнительные поля (например `url`, `timestamp/creation_date`, длины, а для Stack Overflow — `tags`, `score`, `views`)

## Статистика корпуса
Фактические размеры и количество документов зависят от выбранных лимитов/фильтров при извлечении. В типовой конфигурации делается по 50 000 документов из каждого источника (50k Wikipedia + 50k Stack Overflow).

## Проверка требования “существует готовый поиск”
Корпус можно использовать по условию лабы, потому что для обоих источников есть готовый поиск. У Википедии это стандартный поиск MediaWiki (Special:Search) [web:48], у Stack Overflow — встроенный поиск по сайту (по запросу) [web:47].
