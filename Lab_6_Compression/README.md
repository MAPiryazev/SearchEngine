# Отчёт по лабораторной работе 6

## Цель работы
Целью лабораторной работы являлась реализация сжатого представления инвертированного индекса и проверка корректности ключевых компонентов поискового модуля с помощью модульных тестов.

## Реализация сжатого индекса
В проекте подготовлен формат Lab6 для хранения индексов на диске. Прямой индекс сохраняет метаданные документов (URL и заголовок) в файле `index6.fwd`, а инвертированный индекс сохраняет словарь терминов и списки документов в файле `index6.inv`. Для уменьшения размера постингов применяется кодирование разностей (docid gap) и переменно-байтовое кодирование (vbyte). [file:149]

## Построение индексов
Добавлена утилита `index_builder6`, которая загружает документы из MongoDB, выполняет токенизацию с заданными параметрами, формирует прямой и инвертированный индексы и записывает их в каталог вывода. В процессе работы утилита печатает технические метрики, включая число документов и терминов, объём сериализованных постингов и затраченное время построения. [file:149]

## Поиск по индексам
Реализована утилита `bool_search6`, которая открывает сгенерированные файлы индекса, разбирает булевый запрос, преобразует его в ОПН и вычисляет результат, применяя операции AND/OR/NOT над отсортированными списками документов. Результаты выводятся в виде количества совпадений и top документов с восстановлением метаданных из `index6.fwd`. [file:148]

## Тестирование и сборка
Для проверки корректности подготовлен набор модульных тестов (токенизация, режим `keep_numbers`, булевы операции), которые собираются отдельной целью `unit_tests`. Тестовый проект настроен через CMake/CTest и использует Catch2, подключаемый через `FetchContent`, что позволяет получать читаемый вывод тестов без ручной установки зависимостей в систему. Тесты запускаются либо напрямую (`./build/unit_tests`), либо через CTest в verbose-режиме при необходимости дополнительной диагностики. [file:2]
